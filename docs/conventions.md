# Архитектурные соглашения

## Провайдеры данных

Каждый provider данных отвечает за один логический тип данных (агрегат). Его интерфейс и реализация предоставляют операции только над этим типом: `PortfolioTradesProvider` — сделки, `PortfolioPositionsProvider` — позиции, `BondsProvider` — облигации.

Логический тип не обязан соответствовать одной таблице. Provider может читать связанные таблицы и проецировать их в свой тип, но не должен возвращать или изменять посторонние типы данных. Бизнес-расчёты и оркестрация сценариев, объединяющих несколько типов, выполняются в Core или application-сервисе.

Операцию, которая должна атомарно менять несколько типов данных, оформляйте отдельным контрактом конкретного сценария с явной транзакцией. Не добавляйте её в обычный provider одной сущности.

`IPortfolioCashProvider` отвечает только за снимки кеша; расчёт остатков по снимкам, сделкам, операциям фондов и денежным потокам выполняет application service `PortfolioService`. Оценки портфеля и денежные потоки обслуживаются отдельными providers. `IBrokerReportImportProvider` — отдельный контракт атомарного сценария импорта. Это отдельный сценарий, а не образец для новых providers: не добавляйте им ответственности.
