# Закрытые сессии позиций

Самостоятельный агрегат: существующие калькуляторы и providers открытых позиций не изменяются.
Вкладка «Закрытые позиции» страницы `/positions` читает сохранённый результат; «Пересчитать» ставит
фоновую задачу.

## Границы сессии

Идентичность: `SecId + BoardId + CurrencyId`. Первая покупка открывает сессию, нулевой остаток закрывает;
следующая покупка образует новую сессию. Незакрытый остаток не сохраняется.
ID сессии — ID первой покупки; сделки одной даты упорядочиваются по ID для стабильности результата.

Внутри даты сначала продаётся прежний остаток, затем учитываются покупки. Закрытие и повторная покупка
в один день создают две сессии. Если продаж больше прежнего остатка, превышение относится к покупкам этого дня;
выручка и комиссия такой продажи распределяются пропорционально количеству. Продажа сверх всех доступных
покупок прерывает пересчёт с сохранением прежнего снимка. Время исполнения не требуется.

## Показатели

- День покупки включён, день продажи исключён. С даты продажи дневной доход начисляется на уменьшенное количество.
- НКД, оценка: сумма по дням `количество × сумма купона / (дата выплаты − начало периода)`.
  Каждый период использует собственный купон. Это оценка заработанного дохода, не фактические зачисления брокером.
- Тело: `чистая выручка + частичные амортизации − чистая стоимость покупок`.
- Итог: `тело + оценка НКД − комиссии покупок и продаж`.
- Доходность: `итог / сумма всех чистых покупок × 100`.
- Годовая оценка: `итог × 365 / капитал-дни × 100`, где капитал-дни — сумма вложенного капитала,
  умноженного на дни его владения. При докупках и частичных продажах капитал учитывается с даты изменения
  остатка; покупной НКД и комиссия входят во вложенный капитал. При нулевых капитал-днях оценка отсутствует.
  Это линейная оценка без реинвестирования и IRR.

НКД из сделок не меняет «Итого» и «Итого, %»; НКД покупки учитывается только во вложенном капитале для
годовой оценки. Налоги не учитываются. Суммы — в валюте торгов сессии, разные валюты не суммируются.
Частичная амортизация начисляется на остаток после продаж в дату выплаты, исключая покупки этой даты.
Известное полное погашение по дате погашения или возврату всего оставшегося исходного номинала исключается:
владелец сам вносит финальную продажу. Сумма амортизации — `Value`, иначе `ValuePercent × InitialFaceValue / 100`.

## Калькуляторы и полнота данных

`ClosedPositionSessionCalculator` строит сессии и интервалы количества. Фабрика выбирает отдельные файлы:
`DefaultClosedSessionBondCalculator`, `FloaterClosedSessionBondCalculator` (через `BondCouponClassifier`),
`ZoClosedSessionBondCalculator` (номинал USD/EUR/CNY, рублёвые торги). Сейчас все распределяют каждый купон
по дням через `ClosedSessionCouponAccrualCalculator`; правила типов можно менять независимо.
Для флоатеров при отсутствии `Value` и `ValueInRub` повторяется последняя известная сумма купона по длительности текущего периода; Default и ЗО fallback не используют.

ЗО предпочитают `ValueInRub`. При совпадающих валютах используется `Value`; при разных — рублёвая сумма,
иначе курсы ЦБ на каждый день начисления, не позже этого дня. Для амортизации берётся курс на дату выплаты.
Неизвестный курс делает сумму неизвестной. Пустая история допустима только при явно известной частоте купонов 0.
Пробелы, конфликтующие пересечения периодов и неизвестные суммы дают `IsComplete = false` и причину;
идентичные дубли учитываются один раз. Неизвестный купон скрывает купонный и общий результаты, сохраняя тело.
Неизвестная амортизация скрывает тело и итог. Без известного итога/положительной базы проценты отсутствуют.

## Хранение и запуск

`ClosedPositionSessionSourceProvider` читает исходные данные в транзакции `RepeatableRead`.
Сделки после текущей московской даты исключены. Будущая дата выплаты допустима: её период может
охватывать уже закрытую сессию. Курсы после даты расчёта не загружаются.

`ClosedPositionSessionsProvider` атомарно заменяет `ClosedPositionSessions` в транзакции.
Полная перестройка устраняет дубли и устаревшие результаты после изменения/удаления сделок.
Ошибка сохраняет прежний снимок. Задача пересчёта держит распределённую блокировку Hangfire на всём пути
от чтения исходных данных до публикации, в том числе при ручных запусках и на нескольких host-ах.
Модель и миграция хранят числовые поля как `double precision`; переход с `numeric(28,8)` может округлить
ранее сохранённые значения. Снимок производный и пересчитывается из исходных данных.

`ClosedPositionSessionsJob` запускается в `Popo.Jobs` каждые 15 минут в очереди `fast` после первичной загрузки.
Явная распределённая блокировка Hangfire охватывает чтение → расчёт → публикацию, включая ручные запуски
и несколько host-ов. Ошибки логируются; повторы стандартные для Hangfire. В API нет worker-а.

- `GET /api/closed-position-sessions` — сохранённые сессии, последние закрытия первыми.
- `POST /api/closed-position-sessions/recalculate` — `202` и `{ jobId }`; до первичной загрузки — `409`.
- `GET /api/closed-position-sessions/recalculation/{jobId}` — `{ jobId, state }` только для задач этого типа.

Frontend опрашивает ручную задачу раз в 2 секунды, при `Succeeded` перечитывает таблицу.
`Scheduled` — ожидание, включая повторную попытку; `Failed`/`Deleted` — ошибка.
Автоматические изменения видны при следующем открытии страницы или ручном пересчёте.
Миграцию `20261015173849_AddClosedPositionSessions` создаёт EF Core; при запуске её применяет `Popo.Api`.
