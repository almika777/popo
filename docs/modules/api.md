# Popo.Api

Просмотр закрытых сессий и постановка фонового пересчёта используют отдельный
`ClosedPositionSessionsController`; [контракты](closed-position-sessions.md).

## Ответственность

Popo.Api регистрирует Core, HTTP-клиенты, Storage и валидаторы, применяет EF Core-миграции и предоставляет локальные endpoints. Hangfire работает отдельно в [Popo.Jobs](jobs.md).

## Контроллеры по вкладкам

Контроллеры и URL разделены по пользовательским вкладкам:

| Контроллер | Вкладка | Ответственность |
|---|---|---|
| `PortfolioController` | Портфель | сводка, оценки, денежные операции, TWR |
| `PositionsController` | Позиции | позиции и снимок рекомендаций по позициям |
| `TradesController` | Сделки | журнал сделок |
| `LiquidityController` | Ликвидность | текущие позиции фондов денежного рынка |
| `CashRecommendationsController` | Рекомендации | настройки, пресеты и расчёт рекомендаций |
| `BondsController` | MDM | общий поиск облигаций и справочники валют |

`BondsController` является общим MDM-контроллером и используется несколькими вкладками.
Контроллеры не содержат расчёты и обработку ошибок: они вызывают application/Core-сервисы и формируют успешные HTTP-ответы.
Ожидаемые ошибки преобразует в HTTP-статусы общий `ApiExceptionHandler` согласно [ADR-0004](../adr/0004-обработка-ошибок-api-вне-контроллеров.md).

## API

- GET /api/bonds/search?q={query} — поиск облигаций по SecId, краткому или полному наименованию; минимум 3 символа. В ответе `accruedInterest` равен `null`, если НКД отсутствует в справочнике.
- GET /api/bonds/currencies — список валют торгов, найденных в сохранённых данных.
- GET /api/bonds/face-units — список валют номинала, найденных в сохранённых данных.
- GET/POST/PUT/DELETE `/api/trades` — ручной журнал сделок.
- GET `/api/positions` — единый контракт вкладки позиций: текущие позиции, рублёвые итоги и сохранённое состояние рекомендаций. Позиции рассчитываются из сделок с текущей ценой MOEX marketdata, ценовым результатом остатка, рассчитанным по средневзвешенной цене открытых покупок и средним/медианным дневным оборотом в штуках за последние 20 дней. Для стандартных бумаг сохраняется себестоимость, скорректированная к текущему номиналу; для `FaceUnit` USD/EUR/CNY и `CurrencyId` RUB/SUR чистый рублёвый результат сравнивает котировку с фактической рублёвой ценой открытых покупок. Рублёвые флоатеры выбирают отдельный `FloaterPositionCalculator` по `BondType`/`BondSubType`; купонный результат строится из фактических опубликованных сумм каждого периода, текущего `ACCRUEDINT`, НКД покупки и комиссии открытой части. Текущий размер купона не распространяется на прошлые периоды. API загружает полный сохранённый купонный график, включая ближайшую будущую выплату, и считает результат по дате снимка котировки. Если текущий НКД отсутствует или некорректен, новая открытая партия позже снимка или история неполная, чистая оценка остаётся доступна, а купонные и общие показатели скрываются. Покупка флоатера в дату `RecordDate` или за один календарный день до неё тоже делает купонный результат неполным, поскольку в журнале нет даты расчётов сделки. Контракт возвращает фактическую среднюю чистую цену открытых покупок (`averageBuyPrice`), расчётную себестоимость к текущему номиналу, текущий номинал и котировку MOEX в процентах. Средняя цена позиции считается только по покупкам; продажи пропорционально уменьшают количество и себестоимость и не меняют среднюю цену. Внутри даты покупки учитываются до продаж, поэтому время и очередность портфельных сделок не хранятся. Стандартный приблизительный купонный доход сохраняет старую формулу по последнему купону и `CouponPeriod`. Для ЗО используются история MOEX, `RecordDate` и опубликованная рублёвая сумма `ValueInRub` (с валютным курсом как запасным способом); `NextCouponDate` помогает обнаружить пропущенные выплаты. Явная частота 0 из MOEX означает бескупонную бумагу; неизвестная частота не считается нулём. Годовой показатель линейно экстраполирует результат каждой открытой доли покупки на 365 дней; для партии, купленной в день оценки, берётся один день. История MOEX не подтверждает зачисление купонов брокером; амортизационные поступления и реальные выплаты в результат не включаются.
- GET `/api/portfolio?asOf=YYYY-MM-DD` — единый контракт вкладки портфеля: оценки, денежные операции и сводка стоимости позиций и фондов ликвидности.
- GET `/api/recommendations/cash/page` — единый контракт вкладки рекомендаций: пресеты, валюты торгов и валюты номинала.
- POST `/api/liquidity/money-market-funds`, PUT/DELETE `/api/liquidity/money-market-funds/{id}` — ручное управление текущими количеством паёв и средней ценой фондов `LQDT` и `TMON`.
- GET `/api/liquidity/money-market-funds/page` — текущие позиции и варианты фондов для выбора.
- PUT позиции фонда возвращает `200 OK` и сохранённую запись; `204 NoContent` недостаточно, потому что frontend должен получить и отобразить фактические значения после `SaveChangesAsync`.
- Для отображения фондов текущая котировка запрашивается у MOEX по `SecId + BoardId` и кэшируется на один час.
- При добавлении и изменении сделки API принимает `AccruedInterestTotal` — НКД за весь объем сделки; перед сохранением делит его на `Quantity`.
- GET /health — health-check.

Для доходности доступны CRUD-endpoint-ы оценок и внешних денежных операций:

- `GET/POST/PUT/DELETE /api/portfolio/valuations`;
- `GET/POST/PUT/DELETE /api/portfolio/cash-flows`;
- `GET /api/portfolio/return?from=YYYY-MM-DD&to=YYYY-MM-DD`.
- `GET /api/portfolio/benchmark?from=YYYY-MM-DD&to=YYYY-MM-DD&includeLqdt=true&includeIndexedBond=true` — фактическая доходность портфеля рядом с гипотетической доходностью удержания выбранных LQDT и RU000A10F504 за выбранный период. Оба флага по умолчанию `true`; фронтенд передаёт выбранные на графике инструменты.

`GET /api/portfolio/return` возвращает чистую доходность карточки по фактическим полным оценкам всего счёта: налоги и комиссии уже должны входить в оценки, запись `Tax` отражается в `taxes` как справочная сумма и повторно не вычитается. Оценка за предыдущий календарный день нужна только для пополнений и выводов; налог сам по себе такой оценки не требует. Финансовый результат равен `endValue - startValue - deposits + withdrawals`; TWR геометрически связывает сегменты, годовая доходность равна `(1 + periodReturn)^(365 / periodDays) - 1`.

`portfolioProfitPercent` — рост индекса портфеля за период. Начальная стоимость нормируется к 100%; доходности между
соседними оценками связываются геометрически. Пополнения, выводы и налоговые списания убираются из изменения оценки;
поэтому график показывает результат до налогов без влияния внешних денежных потоков. Это не денежная прибыль в рублях.

`comparisonStartDate` — nullable общая дата сравнения: более поздняя из первых дат с данными выбранных инструментов в выбранном диапазоне. Если выбран только LQDT, используется первая дата LQDT; если только RU000A10F504 — первая дата его рассчитанного ряда. Если выбранный инструмент недоступен, поле равно `null`. Портфель и выбранные линии начинаются с общей даты и нормируются к нулю; денежные операции портфеля до неё не включаются. Для фактического портфеля
обязательна оценка ровно на `comparisonStartDate`. Если её нет, числовые поля портфеля равны `null`, `portfolioPoints` пуст,
а `portfolioUnavailableReason` сообщает конкретную дату и просит добавить оценку. Соседняя оценка не используется.

`lqdtProfitPercent` — доходность удержания по ценам LQDT, а не доходность с теми же денежными потоками, что у портфеля.
Если LQDT выбран и `comparisonStartDate` задана, начальная точка — цена на эту дату, а ряд пересчитан относительно неё. Если LQDT не выбран или выбранный набор не имеет общей даты, LQDT возвращается отдельно от первой цены внутри `[from, to]`.
Между котировками изменение цены геометрически распределяется по календарным дням, включая выходные. Для не торговой даты `to`
следующая котировка после `to` используется для интерполяции; если её нет, применяется дневной коэффициент двух последних котировок.
При отсутствии двух котировок для определения коэффициента цена переносится без изменения. `lqdtEndObservationDate` остаётся
датой последней фактической цены не позже `to`. `excessReturn` возвращается как `portfolioProfitPercent - lqdtProfitPercent` за общий период;
если общей даты нет, поле может быть рассчитано только для совместимых границ периода. При отсутствии цены в диапазоне endpoint сообщает, что история недоступна. Берётся
официальная цена закрытия основной сессии MOEX `LEGALCLOSEPRICE` из дневной истории торгов по паю LQDT (не расчётный индикатор LQDTM); комиссии и спред
не моделируются, расходы самого фонда остаются отражены в цене пая. Денежные операции, налоги и портфельные оценки
не меняют доходность LQDT.
Для сравнения API каждый раз получает полную текущую историю LQDT с MOEX, рассчитывает результат по свежему ответу
и сохраняет его в хранилище: наличие граничных строк в кэше само по себе не доказывает, что последняя цена внутри
выбранного периода не пропущена.
Доходность LQDT возвращается независимо от доступности фактической доходности портфеля. Если портфель нельзя
рассчитать из-за отсутствующей оценки или некорректных данных денежных операций, его числовые поля равны `null`,
`portfolioPoints` пуст, а `portfolioUnavailableReason` содержит причину; это не скрывает ряд LQDT.

`indexedBondProfitPercent` — доходность удержания RU000A10F504. Ряд учитывает историческую чистую цену, номинал, ежедневное начисление НКД
и купонные выплаты как денежный остаток без реинвестирования. Внешние пополнения/выводы, налоги, комиссии и спред
в этот сценарий не входят.

Все процентные значения передаются долями (`0.1` = `10%`) и не являются годовой доходностью.
Точки содержат `profitPercent`, который используется для всех линий сравнения.
Для портфельных пополнений, выводов и налоговых списаний нужны оценки на конец дня операции после операции; при отсутствии endpoint
возвращает 400 со списком дат. Обычный `GET /api/portfolio/return` использует отдельную чистую семантику, описанную выше.

Портфельная линия есть только на датах сохранённых оценок; соединение точек не означает ежедневную оценку.
Ряды инструментов и портфеля начинаются на общей дате сравнения, если для портфеля на неё сохранена оценка.

Для настроек и расчёта кандидатов по размещению кеша доступны:

- `GET /api/recommendations/cash` — синхронный расчёт и список отобранных кандидатов;
- `GET /api/recommendations/cash/settings` — настройки активного пресета;
- `PUT /api/recommendations/cash/settings` — валидация и сохранение настроек активного пресета;
- `GET/POST/PUT/DELETE /api/recommendations/cash/presets` и `POST /api/recommendations/cash/presets/{id}/activate` — CRUD
  и активация пресетов стратегии;
- `POST /api/recommendations/cash/recalculate` — синхронный расчёт; возвращает время расчёта и список отобранных кандидатов.

Результат ручного расчёта доступен только в ответе запроса. Автоматического фонового пересчёта cash-кандидатов нет.

Состояние рекомендаций входит в ответ `GET /api/positions`; отдельный `GET /api/positions/recommendation` сохранён для клиентов, которым нужны только рекомендации. Hangfire в `Popo.Jobs` пересчитывает единый снимок каждые 15 минут; при ошибке джоба сохраняет последний успешный результат со статусом `Stale`.

Каждый кандидат содержит `SecId + BoardId`, эмитента, рассчитанную YTM, грязную цену с НКД,
рейтинг, дату погашения и оферты, тип купона и медианный дневной объём в штуках. В `calculation`
возвращаются дата расчётов, рыночная цена в процентах, чистая цена в валюте расчётов, НКД,
грязная цена, номинал и фактически использованные денежные потоки с типом и признаком прогнозного купона.

Настройка минимальной медианы дневного оборота задаётся абсолютным количеством бумаг в штуках:
бумага проходит фильтр при `medianDailyVolume >= minimumMedianDailyVolume`.

Настройки стратегии содержат независимые необязательные фильтры `faceUnit` (валюта номинала) и
`currencyId` (валюта торгов). Если заданы оба, бумага должна соответствовать обоим условиям;
например, `faceUnit = USD` и `currencyId = RUB` отбирает замещающие облигации с долларовым
номиналом, торгующиеся в рублях.

YTM хранится в процентных пунктах (`14.5` означает `14,5%`). Грязная цена включает стоимость
облигации по текущей цене MOEX и НКД. Настройки включают `minimumYtm` и `maximumYtm` в тех же единицах;
в расчёт попадают только облигации внутри этого диапазона.
