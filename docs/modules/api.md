# Popo.Api

## Ответственность

Popo.Api регистрирует Core, HTTP-клиенты, Storage и валидаторы, применяет EF Core-миграции и предоставляет локальные endpoints. Hangfire работает отдельно в [Popo.Jobs](jobs.md).

## Контроллеры по вкладкам

Контроллеры и URL разделены по пользовательским вкладкам:

| Контроллер | Вкладка | Ответственность |
|---|---|---|
| `PortfolioController` | Портфель | сводка, оценки, денежные операции, TWR |
| `PositionsController` | Позиции | позиции и снимок рекомендаций по позициям |
| `TradesController` | Сделки | журнал сделок |
| `CashController` | Кеш | снимки кеша, баланс, фонды и операции фондов |
| `CashRecommendationsController` | Рекомендации | настройки, пресеты и расчёт рекомендаций |
| `BondsController` | MDM | общий поиск облигаций и справочники валют |

`BondsController` является общим MDM-контроллером и используется несколькими вкладками.
Контроллеры не содержат расчёты: они вызывают application/Core-сервисы.

## API

- GET /api/bonds/search?q={query} — поиск облигаций.
- GET /api/bonds/currencies — список валют торгов, найденных в сохранённых данных.
- GET /api/bonds/face-units — список валют номинала, найденных в сохранённых данных.
- GET/POST/PUT/DELETE `/api/trades` — ручной журнал сделок.
- GET `/api/positions` — единый контракт вкладки позиций: текущие позиции, рублёвые итоги и сохранённое состояние рекомендаций. Позиции рассчитываются из сделок с текущей ценой MOEX marketdata, нереализованным результатом, приблизительным результатом с купонным доходом и средним/медианным дневным оборотом в штуках за последние 20 дней. Итоги строятся из того же расчёта позиций без повторного вызова `LoadValuedPositionsAsync`. Контроллер только обрабатывает HTTP-вызов; сбор данных и оркестрацию выполняет `PortfolioPositionsService`, формулы находятся в Core. Приблизительный купонный доход рассчитывается по последнему опубликованному купону из истории бумаги (при отсутствии такого значения используется `CouponValue`) и `CouponPeriod` за дни владения оставшимися FIFO-лотами; НКД сделок игнорируется, из результата вычитается фактическая комиссия покупки этих лотов.
- GET `/api/cash/page?asOf=YYYY-MM-DD` — единый контракт вкладки кеша: снимки, расчётные остатки, валюты, фонды денежного рынка, варианты фондов и операции фондов.
- GET `/api/portfolio?asOf=YYYY-MM-DD` — единый контракт вкладки портфеля: оценки, денежные операции, расчётные остатки и summary. Остатки загружаются один раз и используются одновременно в списке и summary.
- GET `/api/recommendations/cash/page` — единый контракт вкладки рекомендаций: пресеты, валюты торгов и валюты номинала.
- GET `/api/portfolio/summary?asOf=YYYY-MM-DD` — общий объём, позиции, расчётный кеш, фонды ликвидности и результат позиций в рублях.
- GET/POST/PUT/DELETE `/api/cash/snapshots` — ручные снимки фактического остатка валюты.
- GET `/api/cash?asOf=YYYY-MM-DD` — расчётный кеш по последнему снимку с учётом последующих сделок и операций фондов.
- GET/POST/PUT/DELETE `/api/cash/money-market-funds` — ручные позиции фондов денежного рынка `LQDT` и `TMON`.
- GET/POST `/api/cash/money-market-fund-operations` — покупки и продажи фондов, меняющие количество и расчётный кеш.
- GET `/api/cash/money-market-funds/options` — два доступных фонда и их техническая борда `TQBR`.
- PUT для редактируемых cash-сущностей возвращает `200 OK` и сохранённую запись; `204 NoContent` недостаточен,
  потому что frontend должен получить и отобразить фактические значения после `SaveChangesAsync`.
- Для отображения фондов текущая котировка запрашивается у MOEX по `SecId + BoardId` и кэшируется на один час.
- При добавлении и изменении сделки API принимает `AccruedInterestTotal` — НКД за весь объем сделки; перед сохранением делит его на `Quantity`.
- GET /health — health-check.

Для доходности доступны CRUD-endpoint-ы оценок и внешних денежных операций:

- `GET/POST/PUT/DELETE /api/portfolio/valuations`;
- `GET/POST/PUT/DELETE /api/portfolio/cash-flows`;
- `GET /api/portfolio/return?from=YYYY-MM-DD&to=YYYY-MM-DD`.

Расчёт использует общую стоимость портфеля на начало/конец периода, одну оценку на каждую дату и датированные
пополнения, выводы и налоги. Для TWR на каждую дату операции нужна оценка ровно за предыдущий календарный день;
при её отсутствии `GET /api/portfolio/return` возвращает 400 со списком требуемых дат.
Налоги возвращаются отдельным полем и прибавляются к финансовому результату, но не входят во взвешенный капитал.

Для настроек и расчёта кандидатов по размещению кеша доступны:

- `GET /api/recommendations/cash` — синхронный расчёт и список отобранных кандидатов;
- `GET /api/recommendations/cash/settings` — настройки активного пресета;
- `PUT /api/recommendations/cash/settings` — валидация и сохранение настроек активного пресета;
- `GET/POST/PUT/DELETE /api/recommendations/cash/presets` и `POST /api/recommendations/cash/presets/{id}/activate` — CRUD
  и активация пресетов стратегии;
- `POST /api/recommendations/cash/recalculate` — синхронный расчёт; возвращает время расчёта и список отобранных кандидатов.

Результат ручного расчёта доступен только в ответе запроса. Автоматического фонового пересчёта cash-кандидатов нет.

Состояние рекомендаций входит в ответ `GET /api/positions`; отдельный `GET /api/positions/recommendation` сохранён для клиентов, которым нужны только рекомендации. Hangfire в `Popo.Jobs` пересчитывает единый снимок каждые 15 минут; при ошибке джоба сохраняет последний успешный результат со статусом `Stale`.

Каждый кандидат содержит `SecId + BoardId`, эмитента, рассчитанную YTM, грязную цену с НКД,
рейтинг, дату погашения и оферты, тип купона и медианный дневной объём в штуках. В `calculation`
возвращаются дата расчётов, рыночная цена в процентах, чистая цена в валюте расчётов, НКД,
грязная цена, номинал и фактически использованные денежные потоки с типом и признаком прогнозного купона.

Настройка минимальной медианы дневного оборота задаётся абсолютным количеством бумаг в штуках:
бумага проходит фильтр при `medianDailyVolume >= minimumMedianDailyVolume`.

Настройки стратегии содержат независимые необязательные фильтры `faceUnit` (валюта номинала) и
`currencyId` (валюта торгов). Если заданы оба, бумага должна соответствовать обоим условиям;
например, `faceUnit = USD` и `currencyId = RUB` отбирает замещающие облигации с долларовым
номиналом, торгующиеся в рублях.

YTM хранится в процентных пунктах (`14.5` означает `14,5%`). Грязная цена включает стоимость
облигации по текущей цене MOEX и НКД. Настройки включают `minimumYtm` и `maximumYtm` в тех же единицах;
в расчёт попадают только облигации внутри этого диапазона.
