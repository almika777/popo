# Popo.Tests и Popo.Storage.Tests

`Popo.Tests` покрывает контракты и mapping MOEX/CBond, Core-калькуляторы и сервисы рекомендаций,
FluentValidation, EF Core-схему справочных данных, HTTP-контракты API,
строгий калькулятор TWR с обязательными оценками за предыдущий день, пополнениями, выводами и налогами, а также API-контракты ручного ввода оценок
портфеля и денежных операций. Для PUT, возвращающих запись, проверяются статус `200 OK` и значения сохранённой записи;
для PUT с `204 NoContent` запись перечитывается после запроса. Проверка только HTTP-статуса не считается проверкой обновления.

Расчёт позиций тестируется отдельно по фабрике выбора, средневзвешенной цене покупок и пропорциональному сокращению открытых долей продажами, истории выплат, НКД, чистому и общему P&L, полноте графика и годовому показателю. Флоатерские тесты проверяют рост/падение купона и независимость истории от текущего значения, учёт выплаты на дату снимка и исключение даже известной будущей выплаты, прямую рублёвую сумму при неизвестной основной сумме, однократный учёт идентичного дубля, конфликт и некорректные суммы, начало графика относительно покупки, пропущенные первый/средний/последний периоды, пустую историю при известной следующей выплате, неоднозначность сделки около `RecordDate` без даты расчётов, сохранение чистого P&L при отсутствии/ошибке текущего НКД и годовую оценку по каждой открытой доле покупки, включая покупку в дату снимка. `PortfolioPositionsServiceTests` проверяет передачу типа облигации и будущего графика в калькулятор; `PortfolioCouponProviderTests` проверяет чтение будущих строк и фильтрацию по выпуску/борду.

`Popo.Storage.Tests` содержит интеграционные тесты Storage-провайдеров с PostgreSQL в Testcontainers.
`MoexIndexHistoryStoreTests` проверяет upsert по ключу `SecId + TradeDate`, обновление существующей даты,
выборку включительного диапазона по индексу и создание таблицы миграцией.
Правила изоляции тестов в одной общей базе описаны в [ADR-0001](../adr/0001-isolate-tests-within-one-database.md).
