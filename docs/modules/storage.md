# Popo.Storage

`ClosedPositionSessions` хранит отдельный снимок завершённых сессий, публикуемый атомарно.
Entity, configuration и providers отделены от открытых позиций; [подробности](closed-position-sessions.md).

Popo.Storage содержит EF Core-модель PostgreSQL, справочники MOEX/CBond, сделки,
текущие позиции фондов ликвидности, ручные оценки портфеля, внешние денежные операции,
миграции и провайдеры синхронизации.

`PortfolioCouponProvider` инкапсулирует чтение купонного графика по идентичности выпуска `SecId`/`ISIN`; `BoardId` в сохранённом расписании может быть основной доской выпуска, отличной от доски позиции. В график входят дата фиксации владельцев `RecordDate` и опубликованная сумма в рублях `ValueInRub`. `GetPublishedHistoryAsync` ограничивает строки датой оценки; `GetCouponScheduleAsync` также возвращает будущие сохранённые выплаты для проверки полноты расчёта флоатеров. `MoexAmortsAndCouponsUpdateJob` постранично загружает доступную историю купонов и амортизаций MOEX. `PortfolioTrades` хранит дату сделки; время исполнения не хранится, поскольку внутридневная очередность не меняет среднюю цену позиции.

`PortfolioTrades` являются исходными данными для расчёта позиций; отдельная таблица позиций не используется.
`PortfolioValuations` и `PortfolioCashFlows` хранят ручные входные данные доходности портфеля.
Для `PortfolioValuations` действует уникальность даты: на одну дату хранится одна общая стоимость портфеля.
Пополнения, выводы и налоги используются при расчёте доходности портфеля.

`MoneyMarketFunds` хранит текущую ручную позицию фонда: `SecId`, `BoardId`, количество и среднюю цену покупки.
История рыночных котировок в этой таблице не сохраняется; текущая стоимость и результат рассчитываются по котировке MOEX.
Миграция `RemoveMoneyMarketFundOperations` сворачивает прежнюю базовую позицию и операции в текущий остаток, а исходные
строки сохраняет в `ArchivedMoneyMarketFunds` и `ArchivedMoneyMarketFundOperations`. При откате исходная позиция и её
операции восстанавливаются, только если текущая позиция сохраняет исходный `Id`; заменённая позиция с теми же
`SecId`/`BoardId` остаётся без изменений, а старые операции для неё не возвращаются. Архивные таблицы не входят в EF-модель
и не читаются приложением. В MVP разрешены только `LQDT` и `TMON`. `PortfolioMoneyMarketFundsProvider` обслуживает CRUD
текущих позиций напрямую.
`PortfolioValuationsProvider` хранит ручные оценки портфеля, `PortfolioCashFlowsProvider` — пополнения, выводы и налоги.
Правила редактирования записей при `NoTracking` и контракт `PUT /resource/{id}` описаны в
[ADR-0003](../adr/0003-edit-records-with-no-tracking.md).

`PortfolioCurrencyRatesProvider` только читает последние курсы из `CurrencyRates` на дату расчёта и перечисляет валюты,
для которых курс уже доступен. Он не сохраняет ручные курсы аналитики: введённые пользователем значения передаются
только в запросе расчёта.

`MoexIndexHistories` хранит дневные значения индексов MOEX с точностью `numeric(28,12)` и уникальным ключом
`SecId + TradeDate`. `MoexIndexHistoryStore` идемпотентно добавляет новые даты и обновляет уже сохранённые значения.
Первичная и ежедневная синхронизация истории LQDTM выполняется `MoexIndexHistoryUpdateJob`.

`PortfolioBondBenchmarkHistoryProvider` принимает `SecId` и `BoardId`, читает характеристики выпуска по составному ключу
торговой доски и инструмента, затем загружает для диапазона по той же доске дневные `Close`, `LegalClosePrice`, исторические `FaceValue`, `CouponPercent` и `AccInt`
из `MoexHistoryYieldsEntities`. Купонные периоды из `MoexCouponsEntities` включают даты начала, выплаты и фиксации
владельцев, а также опубликованную сумму в рублях (`ValueInRub`, затем `Value` для RUB/SUR).
Периоды охватывают диапазон от опорной исторической котировки до конца выбранного периода, включая незавершённый
купонный период. Выплаты между опорной котировкой и начальной датой нужны для сброса НКД. Расчёт НКД, денежных выплат
без реинвестирования и исполнения по торговым датам выполняет Core, а не provider.

`InvestmentStrategySettings` хранит пресеты стратегии; ровно один пресет активен. Дефолты активного
пресета: рейтинг `AA-`, диапазон погашения 30–730 дней, минимальный медианный оборот 1000 штук,
минимальная и максимальная YTM 15% и 30%, окно оферты 90 дней и тип бумаг «любые».
Пресет также хранит необязательные независимые фильтры валюты номинала `FaceUnit` и валюты торгов
`CurrencyId`; по умолчанию оба не заданы.
В расчёт YTM из `MoexCouponsEntities` передаются опубликованная сумма `Value`, валюта номинала,
номинал на дату купона, дата начала периода и процентная ставка. `Value` приоритетен; `ValueInRub`
не используется как источник договорного потока. Для амортизаций опубликованный `Value` также
приоритетнее `ValuePercent`; процент рассчитывается от первоначального номинала только при отсутствии
суммы. Если обязательный поток нельзя восстановить, выпуск исключается из расчёта.

Все денежные потоки один раз переводятся в валюту расчётов по единому снимку курсов ЦБ на последнюю
доступную дату не позже `SETTLEDATE`. Из `MoexBondSecurities` передаются текущий номинал на дату
расчётов, валюта расчётов, НКД, цена и дата оферты. Запросы графика выполняются с `AsNoTracking` и
точным соответствием `SecId`/`ISIN`.

## Статистика дневных объёмов

`DailyVolumeStatistics` хранит один текущий снимок: строку на `SecId` с `Average`,
`Median`, `HistoryThroughDate` и `CalculatedAt`. Объёмы суммируются по режимам
торгов за дату, затем берутся последние 20 доступных дат с `Volume IS NOT NULL`.
Нулевой объём учитывается; при короткой истории используются все доступные даты.

`DailyVolumeStatisticsStore.RefreshAsync` полностью заменяет снимок в транзакции,
сериализуя параллельные публикации. При ошибке остаётся предыдущий снимок.
`HistoryProvider` читает готовые строки без агрегации истории.
Миграция `AddDailyVolumeStatistics` первоначально заполняет таблицу по существующей истории.
