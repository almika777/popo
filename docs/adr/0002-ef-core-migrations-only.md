# ADR-0002: Миграции схемы только через EF Core

- Статус: Принят
- Дата: 2026-08-09

## Контекст

Схема PostgreSQL описывается моделью `PopoDbContext` и миграциями EF Core. Ручное редактирование
сгенерированных файлов миграций/снимка и выполнение SQL для изменения схемы создают риск
расхождения модели, истории миграций и фактической базы.

## Решение

Все изменения схемы выполняются только штатными командами EF Core:

```powershell
dotnet ef migrations add <MigrationName> `
  --project .\src\Popo.Storage\Popo.Storage.csproj `
  --startup-project .\src\Popo.Api\Popo.Api.csproj

dotnet ef database update `
  --project .\src\Popo.Storage\Popo.Storage.csproj `
  --startup-project .\src\Popo.Api\Popo.Api.csproj
```

Запрещено:

- вручную создавать или переписывать миграции и `PopoDbContextModelSnapshot`;
- применять изменения схемы через прямой SQL в обход EF Core;
- записывать миграции в `__EFMigrationsHistory` вручную.

Сгенерированные EF Core файлы разрешено просматривать и проверять, но не редактировать вручную.

## Последствия

- модель, миграции и база остаются синхронизированы средствами EF Core;
- миграции с потерей данных должны пройти обычную проверку diff и явно отражать эту потерю;
- для нестандартных SQL-операций используется код, сгенерированный или добавленный через миграцию EF Core,
  а не отдельная ручная процедура.
