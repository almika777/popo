# ADR-0001: Изоляция тестов внутри одной PostgreSQL-базы

- Статус: Принят
- Дата: 2026-08-08

## Контекст

Интеграционные тесты `Popo.Storage.Tests` используют PostgreSQL через Testcontainers.
Тесты могут запускаться повторно и параллельно, поэтому общий набор данных, фиксированные
ключи и зависимость от порядка запуска приводят к конфликтам составных первичных ключей и
к нестабильным проверкам.

При этом проект использует одну общую тестовую PostgreSQL-базу. Создание отдельной базы или
контейнера для каждого теста не является принятой архитектурой тестов.

## Решение

Все Storage-тесты используют одну общую PostgreSQL-базу. Изоляция обеспечивается внутри неё:

- каждый тест получает уникальные `SecId`, `TradeId`, даты или другие ключи в зависимости от таблицы;
- тестовые наборы данных не пересекаются с наборами других тестов;
- вспомогательные методы вставки должны быть идемпотентными для составных ключей: использовать upsert или
  обновление существующей записи вместо безусловной вставки;
- проверки фильтруют результат по идентификаторам текущего теста и не используют общий `Single()`;
- тест не удаляет данные, созданные другими тестами;
- результат не должен зависеть от порядка запуска;
- параллельный запуск не должен приводить к конфликтам ключей или изменению данных другого теста.

Для провайдеров, которые по контракту агрегируют все строки портфеля и не имеют фильтра по `SecId`, отдельный тест
использует временную схему PostgreSQL в той же общей базе. Схема создаётся перед тестом и удаляется после него;
отдельная база или контейнер не создаются.

Отдельные базы и контейнеры на тест не создаются.

## Последствия

Положительные:

- сохраняется единая PostgreSQL-среда интеграционных тестов;
- тесты не зависят от порядка и повторного запуска;
- ошибки данных и проверок локализованы набором идентификаторов теста;
- тесты остаются пригодными для параллельного запуска.

Ограничения:

- тестовые вспомогательные методы требуют явной генерации уникальных идентификаторов;
- глобальные портфельные агрегаты требуют временной схемы внутри общей базы;
- проверки агрегатов всего портфеля должны использовать уникальный набор данных или
  явно выбирать принадлежащие тесту записи;
- общее изменяемое состояние между тестами запрещено.
