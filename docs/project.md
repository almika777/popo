# Текущее состояние проекта

## Назначение

`popo` — самостоятельный локальный сервис для принятия решений владельцем облигационного портфеля.
Он синхронизирует данные MOEX ISS, кредитные рейтинги CBond и курсы CBR, сохраняет их в PostgreSQL,
ведёт ручной журнал сделок и рассчитывает позиции, кеш и доходность портфеля.

Это локальный однопользовательский open-source продукт для одного владельца. Пользователи, роли,
регистрация, многопользовательский режим и публичный API не являются частью текущей версии проекта.

Обычный расчёт доходности `GET /api/portfolio/return` использует TWR на дневных оценках; для каждой денежной операции
нужна оценка за предыдущий календарный день, иначе доходность не рассчитывается. Сравнение на вкладке «Индексы»
использует отдельную портфельную линию до налогов: пополнения и выводы нейтрализуются, налоговые списания возвращаются
в стоимость, а на дату операции нужна оценка за тот же день после операции. LQDT и RU000A10F504 показывают доходность
удержания без повторения личных пополнений, выводов и налогов; комиссии и спред также не моделируются. Для RU000A10F504
учитываются ежедневный НКД и выплаченные купоны как денежный остаток без реинвестирования. Кандидаты по размещению кеша
рассчитываются синхронно по запросу и возвращаются списком без сохранения снимка. Рекомендации по открытым позициям
сохраняются в единственном актуальном состоянии и пересчитываются каждые 15 минут.

## Запуск

1. `Popo.Api` загружает конфигурацию и регистрирует зависимости.
2. При старте приложение применяет EF Core-миграции.
3. Отдельный `Popo.Jobs` регистрирует Core, HTTP-клиенты, Storage и Hangfire. В Docker Compose сначала запускается PostgreSQL, затем API применяет миграции, после чего Jobs ждёт готовности API. Hangfire запускает девять ежедневных синхронизационных джоб в `09:00` по московскому времени и мониторинг открытых позиций каждые 15 минут; кандидаты по кешу запускаются только ручным запросом.
4. Джобы получают данные через `Popo.HttpClients` и сохраняют их через `Popo.Storage`.
5. Hangfire Dashboard размещён в Jobs; в Docker доступен по `http://localhost:5110/hangfire`, порт привязан к loopback.

## Проекты

| Проект | Текущая ответственность |
|---|---|
| `Popo.Api` | HTTP-маршруты, прикладные сервисы, DI и миграции базы |
| `Popo.Jobs` | Отдельное приложение, Hangfire, расписание, джобы и Dashboard |
| `Popo.Core` | Бизнесовые контракты и сервисы приложения |
| `Popo.HttpClients` | Клиенты MOEX/CBond/CBR, транспортные DTO MOEX, сериализация и преобразование во внутренние контракты Core |
| `Popo.Storage` | `PopoDbContext`, EF-сущности, конфигурация, миграции и провайдеры PostgreSQL |
| `Popo.Tests` | Тесты контрактов MOEX, преобразований, FluentValidation и схемы PostgreSQL |
| `Popo.Storage.Tests` | Интеграционные тесты провайдеров Storage с Testcontainers PostgreSQL |
| `Popo.Frontend` | Локальный Next.js + Ant Design интерфейс для владельца |

Каталоги `Popo.Moex`, `Popo.Ratings`, `Popo.Sync` и `Popo.Worker` не являются текущими проектами решения.

## Данные

`Popo.Storage` содержит таблицы для активных SEC, облигаций, торговых режимов, исторических доходностей,
купонов, амортизаций, эмитентов, рейтингов облигаций, валютных курсов, сделок, снимков кеша,
операций фондов ликвидности, оценок портфеля и внешних денежных операций.
Также схема содержит настройки стратегии и состояние рекомендаций по открытым позициям; таблица состояния
cash-рекомендаций существует, но текущий ручной endpoint её не заполняет.

## Конфигурация

Строка подключения PostgreSQL читается из `ConnectionStrings:DefaultConnection`.
В Docker Compose по умолчанию используется контейнер `database` с volume `popo-postgres-data`.
Оба host-а получают одну строку подключения через `ConnectionStrings__DefaultConnection`.
Для внешней базы задайте полную `POPO_DB_CONNECTION_STRING` в `.env`.
